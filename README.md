# Sakura Relay

独立的 NovelAI 中转服务与樱花色管理控制台。Sakura NAI 前端填写中转地址和 `skr_` 密钥即可连接。

运行环境：Node.js **22.18+**，建议 Node.js 24。使用原生 HTTP、SQLite 和加密模块，无第三方运行依赖，无需前端构建。

## 下游等级

| 行为 | 普通 Key（standard） | 会员 Key（member） |
| --- | --- | --- |
| 本地点数计价 | 非 Opus 规则 | Opus 规则 |
| NAI5 体力返回 | 固定 0%，isNegative=true | 固定绑定上游的真实有效体力 |
| NAI5 路由 | 账号池优先空闲、最短队列，同等条件轮询 | 绑定体力可免费承接时固定绑定；耗尽后优先其他体力账号，无法免费承接则走 Anlas 池 |
| 非 NAI5、Vibe、Director、放大 | 按账号池分配 | 免费请求优先有效 Opus 池；需要扣点的请求走 Anlas 池 |
| 绑定上游 | 无需且不允许绑定 | 创建时自动绑定 NAI5 剩余额度最高的可用 Opus，编辑时可改绑 |
| 有效期 | 永久 / 指定时间 / 按天 | 永久 / 指定时间 / 按天 |

同一个上游可以绑定多个会员，共享官方体力和恢复过程。不会建立虚拟体力、每日免费上限、下游请求频率限制或“耗尽后付费”开关。

普通 Key 即使实际用了免费 Opus，也按非 Opus 的本地公式扣点。会员 NAI5 的免费资格只取决于**绑定账号**：耗尽后即使账号池选到另一个有体力的 Opus，下游也按付费价格扣点，不继承池中账号的免费体力。

会员的非 NAI5 请求使用本地 Opus 规则，包括现有公式中的免费规格、批量、图生图/重绘强度及附加参考图费用；Vibe 编码、放大等按功能计价，不承诺全部免费。放大虽带有 NAI5 模型标识，也不受会员 NAI5 生图绑定限制。

会员的非 NAI5 免费请求优先分配给有效 Opus 上游，减少免费规格落到非 Opus 账号产生的成本。这个池可以使用任意有效 Opus，不要求等于会员绑定的 NAI5 上游，也不要求有 NAI5 体力，允许 Anlas 余额为零。没有能免费承接的有效 Opus 时回退有足够余额的 Anlas 池，下游仍按原本地报价结算。

会员请求只要本地报价需要扣点（例如超规格、批量、参考图、Vibe 编码、放大），就使用 Anlas 池，不限上游套餐，候选账号必须有正 Anlas 余额且足够支付其本地计算成本；NAI5 绑定账号即使还有体力，这类收费请求也不固定到绑定账号。唯一优先例外是 **NAI5 绑定体力耗尽后**：若其他有效 Opus 的剩余体力可以使本次请求上游成本为零，优先走该体力池，允许该账号 Anlas 为零，**下游仍按耗尽后的本地付费价格扣点**。其他账号的体力不会显示到该会员的订阅里。

绑定账号未开通有效 Opus、体力为零或 isNegative=true 时，会员 NAI5 按体力耗尽处理。绑定账号查询失败、停用或冷却时，NAI5 生成返回明确错误，不能把未知体力当作零并偷偷收费；其他功能仍可走账号池。

## 本地计费与结果结算

概览的最近 7 天 Anlas 图使用双柱对比：下游用量按下游等级对应的本地公式结算，上游用量按实际选中上游的真实套餐及免费资格对应的本地公式计算。系统根据完整结果自动判断成功或失败，成功计入两组用量，失败释放预留且两组消耗均为零。两组数据均使用本地计价，不读取余额差额。

**所有下游扣点在本地计算，不再用上游生成前后的 Anlas 差额结算。**

1. 校验请求参数，使用下游等级对应的 Opus / 非 Opus 计价上下文。NAI5 会员在绑定上游排队出队后，重新查询其真实体力。
2. 本地公式计算准确的下游报价；普通和会员分别计价，忽略客户端传入的 cost/free/anlas 声明。
3. 选择上游时，另用真实上游订阅计算成本，检查免费资格或余额能否承接。此值用于路由和成功后的上游用量统计，不决定下游扣点。Opus 免费池和 NAI5 体力池允许零 Anlas；Anlas 池要求正余额且足够支付上游成本。
4. 在 SQLite 事务中重新检查 Key 的启用状态、有效期和余额，原子预留本地报价。余额不足返回 HTTP 402，不调用生成接口。
5. 完整成功响应按预留的本地报价结算，释放预留；**不查询生成后的上游余额**。
6. 上游拒绝、5xx、超时、断流、响应不完整均自动按失败结算，释放全部预留，下游不扣点，上游用量不计入。成功需要完整返回请求张数对应的结果；HTTP 200 本身不代表生成成功。流式响应不完整时追加错误事件，普通响应不完整时返回 502。

例如：普通 Key 的请求本地报价 26 Anlas，即使上游实际花费 0，也扣下游 26。报价 240 时，即使上游实际花费 220，也扣下游 240。会员免费规格且绑定体力有效时，NAI5 本地报价为 0，余额为零也能生成。

价格公式来自 Sakura NAI 的 `lib/nai/cost.ts`，覆盖模型、分辨率、步数、张数、图生图/重绘强度、SMEA、Opus/NAI5 免费资格、参考图费用。Vibe 编码每次 2 Anlas，已编码 Vibe 不重复收编码费；图片放大按读取到的实际尺寸计价。

增强的普通倍率按提交的目标尺寸与当前模型、步数、Strength 及参考图计价；Noise 不另收费。V5 Max 增强接受图生图的 `upscaled_enhance:true`，请求保留原图尺寸，报价、免费规格判断、上游路由和用量统计统一使用等比扩至约 3,145,728 像素后取整的输出尺寸。Max 超出 Opus 的 1 MP 免费规格，会员也按本地公式扣点；它与 `/ai/upscale` 独立放大接口分别计价。例如 832×1216、V5、28 步、Strength=0.2、单张且无参考图时，普通 1× 为普通 Key 6 / 会员有效体力 0 Anlas，1.5× 为 14 Anlas，Max 为 18 Anlas。

客户端在请求发送后关闭页面，服务仍读完上游响应，完整成功则正常扣点。失败请求立即释放预留，不阻塞后续请求，也不会自动重复生成。

## 排队与多上游

- 所有账号池优先空闲上游；都忙时选择最短队列，队列长度包含正在执行的请求和等待请求；同等队列长度按账号 ID 顺序轮询。不再设置账号权重，账号是否参与由启停开关控制。余额不足或查询失败的候选会在**发送生成前**被跳过。
- 会员非 NAI5 免费请求先按实时订阅和本次成本筛选有效 Opus，再在免费池内按上述规则分配；没有能免费承接的 Opus 时回退 Anlas 池。普通池、免费池、Anlas 池各自记录上一次实际分配的账号，不互相影响；查询、跳过候选和会员固定绑定生成不推进轮询顺序。
- 会员所有需要扣点的请求走 Anlas 池。NAI5 绑定体力耗尽后优先尝试能免费承接的其他体力账号，再回退 Anlas 池；绑定仍有体力且本次下游报价为零时，固定使用绑定上游。
- 同一上游的生成流程串行；不同上游可以同时工作。同一 Key 的多个请求也按先后顺序执行，出队重新检查余额与有效期。会员账号池的只读订阅筛选最多并发查询 4 个账号，不占用生成队列；选中上游出队后再次校验真实订阅和余额，并保持该账号的锁直到生成结束。
- 等待中的请求取消后退出队列，不会稍后自动生成；已经发送给上游的请求继续完成结算。
- 上游停用时不生成。上游自身返回 429 时原样提示并短暂冷却，不自动重试已发送的生成。
- 删除已绑定会员的上游时，实时查询其他可用 Opus，将所有未删除会员自动换绑到 NAI5 剩余额度最高的上游，再移除原上游；停用、冷却、失效、查询失败或正在编辑的账号不参与选择，额度相同时按账号 ID 排序，所有有效账号额度为零时仍可换绑。没有可用替代账号时保留原上游和绑定；换绑与移除在同一事务中完成，历史请求与流水保留。绑定会员正在执行或排队时暂不能删除上游；执行或排队期间不能更改下游等级与绑定，启停和有效期变更会在受理后续请求前生效。
- 上游有正在执行的任务时，不能更换官方凭据或删除。任务完成或失败后解除限制，移除上游不删除历史记录。
- 服务是单实例架构：不要给同一数据目录运行多个进程或副本。进程锁、SQLite 预留和内存队列共同保证串行与不透支。

`Idempotency-Key` 可用于防重复提交。同一个下游 Key 重复使用已受理的请求编号返回 409，不会重新生成。相同 prompt 本身不去重。

## 订阅返回与有效期

普通 Key 的 `/user/subscription` 完全在本地返回：tier=1、NAI5 usage 为零、余额为自己的余额减预留，不需要查询上游。会员返回 tier=3 和绑定上游的真实有效 usage。两种等级的 active/expiresAt 都按下游有效期处理，不使用上游到期时间；永久 Key 不返回 expiresAt。

`relay` 包含等级、到期时间（毫秒）、余额、预留、可用余额、绑定上游 ID 和体力来源。官方兼容字段 expiresAt 使用秒。后台上游额度查询仍显示真实套餐、到期时间、Anlas 与 NAI5 体力，不使用下游等级。

- 创建 Key 可选永久、从创建起若干天、指定日期时间。
- 编辑可保持到期时间、改为永久、指定时间或续期若干天。
- 续期从“现在与原到期时间的较晚者”起计算。
- 到期返回 HTTP 403 与 `KEY_EXPIRED`，不清零余额或历史。
- 充值不会续期，重新启用不会续期。已受理的请求继续结算。
- 到期判断同时在请求鉴权、排队后和原子预留时执行，不依赖定时任务。

## 控制台与启动

密钥列表的“删除”和密钥详情的“删除密钥”均会先显示确认弹窗。删除后密钥立即失效、从列表与可用余额统计中移除，剩余 Anlas 不再可用，不能重新启用或续期；历史请求、Anlas 流水和用量统计保留。删除会员密钥会解除该密钥对上游的绑定占用。有生成或排队请求的密钥暂不能删除，需等待请求结束。

```powershell
cd D:\code\sakura-nai-relay
npm start
```

也可以双击 `start-local.cmd`。默认监听 `127.0.0.1:3100`，打开 <http://127.0.0.1:3100>。

首次启动读取 `.data/setup-code.txt` 的初始化码，设置至少 12 字符的管理员密码；初始化后该文件删除。管理会话有效 12 小时，使用 HttpOnly Cookie，写操作检查 Origin 与 CSRF。

1. 上游设置：添加官方 Persistent API Token、名称，通过启停开关控制是否参与分配。保存时仅执行账户查询；账号卡片显示余额和排队请求数。
2. 访问密钥：选择普通/会员、初始点数、有效期。会员创建时实时查询可用 Opus，自动绑定 NAI5 剩余额度最高的账号；停用、冷却、失效或查询失败的账号不参与选择。额度相同时按账号 ID 确定顺序，所有有效账号额度为零时仍可创建；没有有效 Opus 时提示创建失败。
3. 在绘图网页填写中转地址和 `skr_` Key。其他域名需在控制台添加允许来源；在“允许的来源”填写 `*` 并保存，即可允许所有来源访问中转接口，仍需有效的 `skr_` Key。指定站点时每行填写一个完整来源，包含协议和端口，不含路径。
4. 通过“编辑 / 续期”调整等级、绑定和时效，通过“调整点数”增减余额。

完整上下游密钥均 AES-256-GCM 加密保存。下游鉴权使用摘要。完整下游 Key 只在管理员登录、Origin 与 CSRF 校验通过后，通过单独接口查看，不出现在列表或概览中。备份必须同时保留数据库与 `.data/master.key`。

## 从早期版本升级

本次不兼容旧下游 Key。第一次打开旧数据库时，旧 Key、任务与流水分别归档到 `archived_keys`、`archived_jobs`、`archived_ledger`，旧 Key 立即失效，控制台需要重新创建 Key。管理员设置、加密主密钥和多上游账户保留。归档只用于保留历史，不参与鉴权、路由或计费；后续重启不会再次清理新 Key。

移除账号权重时，原权重为零的上游自动转为停用，其他账号保留原启停状态；已有新等级密钥、会员绑定、余额和流水均保留。迁移后只通过启停开关管理账号。

升级前停止旧进程并备份数据。不要让旧进程与新进程同时访问同一个数据库。

## Linux / Docker

```bash
cp .env.example .env
# 修改 PUBLIC_ORIGIN=https://relay.example.com
# 并设置 COOKIE_SECURE=true
docker compose up -d --build
docker compose exec relay cat /app/data/setup-code.txt
```

Docker 默认只把端口映射到宿主机回环地址。前面使用 HTTPS 反向代理。宿主机 Caddy 示例：

```caddy
relay.example.com {
    reverse_proxy 127.0.0.1:3100 {
        flush_interval -1
    }
}
```

宿主机 Nginx 可使用下列 `location` 放入已有 HTTPS `server`：

```nginx
location / {
    proxy_pass http://127.0.0.1:3100;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;
    proxy_read_timeout 150s;
    client_max_body_size 32m;
}
```

`PUBLIC_ORIGIN` 必须与浏览器实际打开的协议、域名及端口相同，否则管理写操作会被拒绝。HTTPS 下使用 Secure Cookie。接口与控制台默认同域。下游请求不设置每分钟限频；同一 Key 和同一上游均串行排队。管理员登录、改密码等管理操作仍保留保护。

配置项见 `.env.example`。`UPSTREAM_ORIGIN` 默认官方图片域名，只能通过服务端环境变量修改，不允许客户端指定目标域名。路由使用白名单，不提供任意 URL 转发。管理页面没有第三方脚本、字体或外部资源。

## 备份与恢复

维护前先停止服务，再备份整个数据目录（Docker 为 `relay-data` 卷），包括 `relay.sqlite`、可能存在的 WAL 文件、`master.key`。**丢失 master.key 无法解密官方 Key**。不要只复制运行中的单个 SQLite 文件。

恢复到另一台机器时，在服务停止状态还原数据目录，删除备份中的 `process.lock`，再启动。未完成请求在启动时自动判为失败并释放预留，不自动重试；已有旧核对任务也自动按失败结算。初始化后普通备份里不再包含有效初始化码。Windows 上应限制数据目录仅当前用户和管理员可读。

## 代码结构

```text
src/index.mjs       启动、进程锁与配置
src/server.mjs      管理 API、跨域、路由与转发
src/db.mjs          SQLite、等级/绑定/有效期、点数预留与流水
src/security.mjs    密码、会话与上游密钥加密
src/billing.mjs     请求计价校验、额度字段与流式完整性检查
src/cost.mjs        从前端搬来的 Anlas 计算逻辑
src/image-size.mjs  读取实际图片尺寸，校验图片处理计价
src/router.mjs      多上游空闲优先、最短队列、轮询与串行调度
src/queue.mjs       按 Key 和上游分别串行的可取消 FIFO 队列
src/upstream.mjs    只读账户查询和有限响应读取
public/            樱花色管理控制台
tests/             本地模拟上游与集成测试
```

计价预留公式的来源和许可见 `THIRD_PARTY_NOTICES.md`。
