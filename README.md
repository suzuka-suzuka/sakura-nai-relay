# Sakura Relay

独立的 NovelAI 中转服务与樱花色管理控制台。连接已有 Sakura NAI 前端时，无需修改绘图网页：在高级连接设置中填写中转地址和 `skr_` 访问密钥即可。

运行环境：Node.js **22.18+**，建议 Node.js 24。使用原生 HTTP、SQLite、加密模块，无第三方运行依赖、无需前端构建。Node 22 的 SQLite 实验性警告不影响启动。

## 能做什么

- 初始化管理员、密码登录、修改密码、退出；12 小时 HttpOnly 会话，写操作检查 Origin 与 CSRF。
- 创建第三方 Key，命名、分配初始 Anlas、增加或扣减 Anlas、启用或停用。
- 管理员可随时查看、复制完整访问密钥；访问密钥与上游官方 Key 均使用 AES-256-GCM 加密保存，访问鉴权仍校验摘要。
- 概览显示密钥数量、余额合计、消耗与七天用量图；请求记录与 Anlas 流水持久化到 SQLite。
- 多上游账户管理：命名、添加或更换官方 Key、权重（0–1000）、启停和移除。
- 逐个查询官方 Anlas 余额与 NAI 5 额度，独立进度条；Anlas 可合计，NAI 5 百分比按账户显示。
- 第三方 `/user/subscription` 使用真实官方 Key 查询：保留订阅和 `usage`，将 Anlas 余额替换为当前第三方 Key 的可用 Anlas，避免误显示整个官方账户的钱。
- 生成、实时预览、Vibe 编码、标签建议、Director 图片处理、图片放大。
- 同一上游串行生成、Anlas 预留、异常记录、人工核对；不自动重试付费请求。

## 本地启动

```powershell
cd D:\code\sakura-nai-relay
npm start
```

也可以双击 `start-local.cmd`。默认仅监听 `127.0.0.1:3100`，打开 <http://127.0.0.1:3100>。

首次启动会生成 `.data/setup-code.txt`。将其中的初始化码填写到网页，设置至少 12 字符的管理员密码。成功初始化后，初始化码失效并删除文件；没有预置管理员密码。

然后：

1. **上游设置 → 添加上游**：填写名称、NovelAI 官方 Persistent API Token 和权重，可添加多条。保存时会执行一次只读账户查询，验证成功才保存。不要把真实 Token 发到聊天或提交 Git。
2. **访问密钥**：创建 Key，填写初始 Anlas；之后可随时点击「查看密钥」查看、复制完整 `skr_` Key。
3. **Sakura NAI 绘图网页**：高级连接设置 → 接口地址填 `http://127.0.0.1:3100`，访问密钥填新建的 `skr_` Key。
4. 如果绘图网页使用其他域名，在上游设置中添加对应来源，例如 `https://studio.example.com`。

当前默认允许 `http://127.0.0.1:3000` 和 `http://localhost:3000`。首次配置上游不会自动执行付费生成。

旧版仅存摘要的访问密钥无法直接还原，但继续有效。启用的旧密钥下次通过客户端认证（查询额度即可）时会自动加密补存，之后可在后台查看。如果原密钥已丢失，可在详情中重新生成：旧密钥失效，Anlas、启停状态和历史记录保留。完整密钥只通过需要管理员登录、Origin 与 CSRF 校验的单独接口返回，不包含在列表或概览响应中。备份时须同时保留数据库与 `.data/master.key`。

## Anlas 与计费边界

**访问密钥直接分配 Anlas，按上游实际 Anlas 消耗扣除，免费生成不扣除余额。**

1. 每次付费操作前，用真实官方 Key 读取账户余额及 NAI 5 额度。
2. 在后端使用从 Sakura NAI 的 `lib/nai/cost.ts` 搬来的计价规则计算预留 Anlas，检查第三方 Key 的「余额减预留」是否足够。覆盖分辨率、步数、张数、图生图/重绘强度、SMEA、Opus/NAI 5 免费额度和参考图费用；不信任客户端声明的价格。放大读取实际图片尺寸，按同样的 1／2／3／4 Anlas 档位计算。
3. 原子预留 Anlas，将请求送往上游。上游忙时返回 `429` 和 `Retry-After`，不在服务器内无界排队。Sakura NAI 的现有 429 退避机制可继续使用。
4. 完整响应后立即再次查询余额，按可确认的 Anlas 余额差结算并释放预留；仅在余额未更新或查询失败时，最多追加两次短间隔查询。
5. 上游返回 429 时直接按未受理结算为 0，释放预留；其他明确拒绝且余额没变化时不扣 Anlas。超时、断流、重启、无法查询余额、余额增加、扣费超过预留，以及预计收费但余额尚未变化，都会保留预留并转入「待核对」。有待核对任务时只暂停对应上游的新生成，其他上游照常工作。管理员核对后可结算实际 Anlas，确认未收费则填 0。

例如：本地计算需 240 Anlas，但访问 Key 可用余额只有 1，则返回 HTTP 402，**不会调用上游生成接口**。可用余额为 240 时先预留 240；如果真实消耗 220，则扣除 220 并释放剩余 20。免费生成按实际消耗 0 结算。Vibe 编码作为单独请求预留 2 Anlas，已编码 Vibe 不重复收编码费用。

同一上游从生成前查询到生成后结算全程串行。上游 429 不会将其他请求的余额变化算到此请求上。无需勾选“账户专用”确认。余额差仍受订阅重置、充值或扣费尚未更新等变化影响；这些异常保留记录并核对，不自动重新生成。

客户端关闭或断开后，已经发送的上游请求继续读完并核对用量，避免浏览器取消成为逃避扣费的途径。暂停/停用影响后续请求，已开始的请求仍然结算。

服务使用单实例、多个上游 Key。不要给同一数据目录运行多个进程或多个副本。启动脚本有进程锁，SQLite 事务负责预留，同一个上游同一时刻只能有一个未结算任务；同一个访问 Key 也只能有一个进行中的付费请求。暂不提供支付充值或公开用户注册。

## 多上游路由

- 使用平滑加权轮询。权重 1 和 2 的两个空闲上游，持续顺序请求按约 1:2 分配。权重为 0 或停用的上游不分配请求，但仍可查额度。
- 不同上游可同时处理不同访问 Key 的请求。同一请求的生成前查询、生成、生成后查询始终使用同一上游；不在付费调用中途自动切换 Key。
- 第三方查询订阅时，暂时绑定所选上游 30 秒；紧接着的生成使用该上游。查询本身不推进轮询。绑定过期或上游停用、异常后会重新选择；服务器每次生成前仍重新读取真实订阅状态并重新计价。
- 后台查额度会查询全部上游，最多四个同时进行；某个失败不影响其他结果。第三方看到所选上游的真实 NAI 5 额度和自己的 Anlas 余额。
- 忙碌上游会被跳过；已绑定的上游正忙则返回 429。查询失败或上游鉴权/限流失败会进入短暂冷却，其他上游仍可服务。待核对上游在完成核对后恢复。
- 不允许重复保存同一官方 Key。记录保留脱敏尾号；每笔请求保存上游 ID 与当时名称。上游有进行中或待核对任务时，不能更换 Key 或移除。
- 旧单 Key 配置自动迁移成第一条上游记录。已有管理员、访问 Key、Anlas、历史请求和流水保留。移除上游不删除历史流水。

`Idempotency-Key` 可用于调用方防重复提交；同一 Key 上重复使用该请求编号会返回 `409`，不会再次生成。现有 Sakura NAI 前端未自动发送该字段；中转也不会对用户主动发起的所有相同内容请求做去重。

## Linux / Docker

```bash
cp .env.example .env
# 修改 PUBLIC_ORIGIN=https://relay.example.com
# 并设置 COOKIE_SECURE=true
docker compose up -d --build
docker compose exec relay cat /app/data/setup-code.txt
```

Docker 默认只把端口映射到宿主机回环地址。前面使用 HTTPS 反向代理。宿主机 Caddy 示例：

```caddy
relay.example.com {
    reverse_proxy 127.0.0.1:3100 {
        flush_interval -1
    }
}
```

宿主机 Nginx 可使用下列 `location` 放入已有 HTTPS `server`：

```nginx
location / {
    proxy_pass http://127.0.0.1:3100;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;
    proxy_read_timeout 150s;
    client_max_body_size 32m;
}
```

`PUBLIC_ORIGIN` 必须与浏览器实际打开的协议、域名及端口相同，否则管理写操作会被拒绝。HTTPS 下使用 Secure Cookie。接口与控制台默认同域。服务不信任客户端的 `X-Forwarded-For`，反向代理后的 IP 限速会按代理地址聚合；每 Key 限速仍然独立。

配置项见 `.env.example`。`UPSTREAM_ORIGIN` 默认官方图片域名，只能通过服务端环境变量修改，不允许客户端指定目标域名。路由使用白名单，不提供任意 URL 转发。管理页面没有第三方脚本、字体或外部资源。

## 备份与恢复

维护前先停止服务，再备份整个数据目录（Docker 为 `relay-data` 卷），包括 `relay.sqlite`、可能存在的 WAL 文件、`master.key`。**丢失 master.key 无法解密官方 Key**。不要只复制运行中的单个 SQLite 文件。

恢复到另一台机器时，在服务停止状态还原数据目录，删除备份中的 `process.lock`，再启动。未完成请求会转为待核对，不自动重试。初始化后普通备份里不再包含有效初始化码。Windows 上应限制数据目录仅当前用户和管理员可读。

## 验证

```bash
npm run check
npm test
```

测试通过本地模拟上游覆盖鉴权、CSRF、CORS、免费与付费、额度透传、并发、幂等、Vibe/放大、流式断流、预留、异常结算及重启恢复，**不会请求官方生成或消耗实际额度**。

本地界面预览（仅模拟数据，与正式数据分开）：

```bash
node scripts/preview.mjs
```

地址为 `http://127.0.0.1:3101`，测试密码 `Sakura-Preview-2026`。该预览仅监听本机、上游也是本地 mock；不要用它做正式部署。正式服务始终使用 `.data`，预览使用 `.preview`。

接口以当前 Sakura NAI 客户端与 [NovelAI 官方接口文档](https://image.novelai.net/docs/doc.json) 为依据。实际官方账户的付费生成、账户限制、扣费更新时间及 Docker 镜像构建，需要部署后用自己的账户和环境验证。

## 代码结构

```text
src/index.mjs       启动、进程锁与配置
src/server.mjs      管理 API、跨域、路由与转发
src/db.mjs          SQLite、密钥、Anlas 预留与流水
src/security.mjs    密码、会话与上游密钥加密
src/billing.mjs     请求计价校验、额度字段与流式完整性检查
src/cost.mjs        从前端搬来的 Anlas 计算逻辑
src/image-size.mjs  读取实际图片尺寸，校验图片处理计价
src/router.mjs      多上游加权路由、占用和短时绑定
src/upstream.mjs    只读账户查询和有限响应读取
public/            樱花色管理控制台
tests/             本地模拟上游与集成测试
```

计价预留公式的来源和许可见 `THIRD_PARTY_NOTICES.md`。
