# Sakura Relay

独立的 NovelAI 中转服务与樱花色管理控制台。Sakura NAI 前端填写中转地址和 `skr_` 密钥即可连接。

运行环境：Node.js **22.18+**，建议 Node.js 24。使用原生 HTTP、SQLite 和加密模块，无第三方运行依赖，无需前端构建。

兼容 [Aaalice NAI Launcher](https://github.com/Aaalice233/Aaalice_NAI_Launcher) 使用的 `multipart/form-data` 请求：生成、图生图、重绘、Vibe 编码、图像处理和放大均可通过 `request` JSON 分块与二进制图片分块提交。生成参考图的 `reference_image_multiple_cached`、`director_reference_images_cached` 按实际条目数纳入本地计费和模型限制校验，重复引用同一图片分块不会减少参考图费用。

流式生成按客户端的 `parameters.stream` 返回：`msgpack` 返回带 4 字节大端长度前缀的 MessagePack 帧，其他请求返回 SSE。服务仍向上游请求 SSE 并检查完整结果，再转换 Launcher 所需的预览与最终图片事件；不完整流或错误事件会释放预留并返回对应格式的失败事件。

若 Launcher 显示 HTTP 415「需要 JSON 或受支持的放大表单」，说明运行中的中转仍使用仅支持 JSON 生成的旧代码。更新中转代码并重启服务；Docker 部署执行 `docker compose up -d --build`。只关闭实时预览不能解决旧服务拒绝普通 multipart 生成的问题。

## 下游等级

| 行为 | 普通 Key（standard） | 会员 Key（member） |
| --- | --- | --- |
| 本地点数计价 | 非 Opus 规则 | Opus 规则 |
| V5 体力 | 固定 0% | 本地独立分配，百分比保留一位小数 |
| 固定绑定上游 | 无 | 无，统一使用账号池 |
| 有效期 | 永久 / 指定时间 / 按天 | 永久 / 指定时间 / 按天 |

会员创建时设置体力上限（0–100%，默认 25%）。0% 不分配或恢复 V5 体力，仍保留 V4.5 等非 V5 模型的会员免费规格权益。100% 容量是 1,120 张 V5，从 Key 创建时间起每满 24 小时恢复 160 张；25% 容量是 280 张，每满 24 小时恢复 40 张，其他比例依此计算。**新建会员 Key 时直接发满所分配的上限**：100% 的新 Key 初始 1,120 张，接口显示 100.0%；25% 初始 280 张，显示 25.0%。已有 Key 除本次启动一次性补满外，不会在后续重启时补发体力。例如北京时间 15:30 创建的 Key，之后每天 15:30 到达下一恢复周期，延迟查询不会改变这个时刻。满额后的恢复量丢弃，不额外积攒。查询、生成与后台列表按创建起经过的完整 24 小时周期补算，无需给每个 Key 建立定时任务；服务停机也会补算未处理的周期，最多恢复至容量上限。

兑换码 SKU「月卡：V4.5无限小图(无V5体力)」（`month-v45`）位于「月卡：4人Opus无限小图(无点)」之前，兑换后创建 30 天会员 Key，初始点数及 V5 体力均为 0。V4.5 沿用会员免费小图规则：单张、面积不超过 1,048,576 像素、步数不超过 28，参考图等附加费用仍按现有规则计费。

V5 符合现有 Opus 免费规格（面积不超过 1,048,576 像素、步数不超过 28）时，一次请求最多抵扣一张，成功扣一张本地体力；批量的其他图片按点数计费。超规格请求按点数计费，不扣体力。体力不足一张时按本地付费价格计费，即使实际上游免费也仍扣下游点数。其他模型和图片工具保留现有会员计价，不消耗 V5 体力。

**使用本地体力抵扣的请求必须由真实 V5 体力可用的有效 Opus 承接。** 批量还要求该上游有足够 Anlas 支付其余图片。没有符合条件的上游时返回 HTTP 503 与 UPSTREAM_STAMINA_UNAVAILABLE，提示“上游暂时无法承接本次请求，请稍后重试”；不回退到耗尽体力的付费账号，不扣下游点数或体力。实际发出生成后上游拒绝时也不会自动重发。

非 V5 免费请求优先有效 Opus，不要求有 V5 体力；没有能免费承接的 Opus 时回退余额足够的 Anlas 池。普通 Key 即使实际使用免费 Opus，仍按普通本地价格扣点。

上游账户以列表显示，已启用与已停用账户分区显示，已停用固定在下方。点击过期时间、点数或 NAI5 体力列标题可切换升降序，各分区独立排序；首次点击或切换到点数、体力列时默认从高到低，过期时间默认从近到远。未知额度和过期时间排在所在分区末尾。点击“上游名称”恢复各分区的默认添加顺序，重复点击不会倒序。排序在当前页面会话内保留，实时更新后仍按所选列排列。上游名称可直接填写账户邮箱或标识；添加和编辑时可填写多行备注（最多 1000 字），旧数据的备注自动补为空白。

上游独享、会员固定绑定和自动换绑机制已移除。上游统一通过启停开关参与账号池。调整点数不会自动改变体力档位；续期、改名和提高上限不会补满体力，降低上限会截断超出部分。

## 本地计费与结果结算

概览顶部显示访问密钥、上游密钥、今日活跃和正在生成。访问密钥仅计启用且未过期的密钥，上游密钥仅计启用项；今日活跃按北京时间当天发起并进入上游执行的图片任务去重统计访问密钥，正在生成统计尚未结束的上游图片任务（包含生图、流式生图、图片处理和放大，不含 Vibe 编码或排队请求）。四项随实时推送更新。

概览新增 V5 体力与 Anlas 对比：上游剩余为启用上游的当前额度，V5 仅计有效 Opus；下游剩余为启用且未过期的 Opus 会员密钥的剩余额度，扣除预留，体力与 Anlas 均不计普通密钥。V5 百分比按账户相加，可超过 100%；差额为上游剩余减下游剩余。上游额度未查到或查询失败时，对应上游剩余与差额显示「—」。数据随现有实时推送更新。

概览的最近 7 天 Anlas 图使用双柱对比：下游用量按下游等级对应的本地公式结算，上游用量按实际选中上游的真实套餐及免费资格对应的本地公式计算。系统根据完整结果自动判断成功或失败，成功计入两组用量，失败释放预留且两组消耗均为零。两组数据均使用本地计价，不读取余额差额。

**所有下游扣点在本地计算，不再用上游生成前后的 Anlas 差额结算。**

1. 校验请求参数，使用下游等级对应的 Opus / 非 Opus 计价上下文。使用下游本地体力判断免费资格，上游出队后重新查询其真实订阅与体力。
2. 本地公式计算准确的下游报价；普通和会员分别计价，忽略客户端传入的 cost/free/anlas 声明。
3. 选择上游时，另用真实上游订阅计算成本，检查免费资格或余额能否承接。此值用于路由和成功后的上游用量统计，不决定下游扣点。Opus 免费池和 NAI5 体力池允许零 Anlas；Anlas 池要求正余额且足够支付上游成本。
4. 在 SQLite 事务中重新检查 Key 的启用状态、有效期和余额，原子预留本地点数与体力。余额不足返回 HTTP 402，不调用生成接口。
5. 完整成功响应按预留的本地报价结算，释放预留；**不查询生成后的上游余额**。
6. 上游拒绝、5xx、超时、断流、响应不完整均自动按失败结算，释放全部预留，下游不扣点，上游用量不计入。成功需要完整返回请求张数对应的结果；HTTP 200 本身不代表生成成功。流式响应不完整时追加错误事件，普通响应不完整时返回 502。

Anlas 流水只记录非零点数变化：创建时分配点数、充值、人工增减点数，以及成功生成后的实际扣点。零点创建、零点调整、免费生成和失败请求不写流水；已有零点流水也不出现在列表中。请求记录仍保留免费生成和失败任务，包括本地体力的实际结算。

生成、流式生成及图片工具请求在进入服务时持久化记录，选定上游并开始执行后才在列表及 SSE 中显示；若此前失败或取消，则直接显示最终状态和原因。来源或密钥校验失败、参数错误、余额不足、无可用上游、上游查询失败和重复提交都会保存具体原因。上传或排队期间断开连接显示“已取消”，不扣点数或体力；已经开始的上游生成仍按最终结果结算，并注明客户端已断开。服务重启会把尚未转发的等待请求标记为失败。额度查询、标签查询与预检记录失败或取消，成功查询不增加请求记录。详情显示请求阶段、响应状态及独立的上游 HTTP 状态；未知密钥显示“未识别密钥”，不保存提交的原始凭据。请求记录可按“全部 / 失败”筛选，默认显示全部；失败筛选包含已取消的请求，全部包含已选定上游的处理中请求，并与 Key 搜索组合；从完整历史中返回最近 100 条匹配记录。历史未记录的失败无法补回；未到达应用的网络或代理层错误不在此日志范围内。

例如：普通 Key 的请求本地报价 26 Anlas，即使上游实际花费 0，也扣下游 26。报价 240 时，即使上游实际花费 220，也扣下游 240。会员免费规格且本地及上游体力有效时，NAI5 本地报价为 0，余额为零也能生成。

价格公式来自 Sakura NAI 的 `lib/nai/cost.ts`，覆盖模型、分辨率、步数、张数、图生图/重绘强度、SMEA、Opus/NAI5 免费资格、参考图费用。Vibe 编码每次 2 Anlas，已编码 Vibe 不重复收编码费；图片放大按读取到的实际尺寸计价。

局部重绘与扩图使用 `action:infill` 和对应的 `-inpainting` 模型，原图、黑白蒙版必须与本次请求尺寸一致；不一致的请求会在扣点和访问上游前拒绝。V4/V4.5/V5 的嵌套 `img2img.strength` 与 `inpaintImg2ImgStrength` 同时出现时必须相同，按实际重绘强度计价。细节重绘的裁切与生成后蒙版合成由前端完成，relay 只按实际请求尺寸计价、保留原图和蒙版转发。V4.5 Variety+ 的 `skip_cfg_above_sigma` 完整转发，不另加点数。会员有效 Opus 的独立放大在输入面积不超过 640×640 时免费，与前端报价一致；普通密钥及较大图片仍使用现有面积档位。

增强的普通倍率按提交的目标尺寸与当前模型、步数、Strength 及参考图计价；Noise 不另收费。V5 Max 增强接受图生图的 `upscaled_enhance:true`，请求保留原图尺寸，报价、免费规格判断、上游路由和用量统计统一使用等比扩至约 3,145,728 像素后取整的输出尺寸。Max 超出 Opus 的 1 MP 免费规格，会员也按本地公式扣点；它与 `/ai/upscale` 独立放大接口分别计价。例如 832×1216、V5、28 步、Strength=0.2、单张且无参考图时，普通 1× 为普通 Key 6 / 会员有效体力 0 Anlas，1.5× 为 14 Anlas，Max 为 18 Anlas。

客户端在请求发送后关闭页面，服务仍读完上游响应，完整成功则正常扣点。失败请求立即释放预留，不阻塞后续请求，也不会自动重复生成。

## 排队与多上游

- 账号池优先空闲上游；都忙时选最短队列。真实上游点数请求（普通池和 Anlas 池）先用非 Opus 账号。无订阅、Tablet、Scroll 都算非 Opus，彼此不区分到期时间，因为只有有效 Opus 的小图和标准图不耗点数。没有空闲非 Opus 时，再按 Opus 到期时间从早到晚选择，没有到期时间的排在后面。正在使用的账号不会挡住空闲的下一个。Opus 免费池和 V5 体力池仍按账号 ID 轮询，各池分开记录；查询和跳过候选不推进轮询。
- 使用本地 V5 体力的请求只选择真实体力足够的有效 Opus，不能回退付费上游。本地 V5 体力耗尽后的点数请求可以优先借用能免费承接的 Opus，下游仍按点数收费，再回退 Anlas 池。超规格和其他付费项目保留 Anlas 池规则。
- 同一上游生成串行，不同上游可以同时工作；同一 Key 按顺序执行，出队检查余额、体力和有效期。只读订阅筛选最多并发查询 4 个账号，不占生成队列；选中上游后加锁并重新校验，保持锁直到结算。
- 等待时取消请求会退出队列；已发送给上游的请求继续完成结算。上游 429 会提示并短暂冷却，不自动重发。
- 生成或排队期间不能修改下游等级或体力上限，也不能删除下游。上游有执行中任务时不能更换官方凭据或删除；移除上游保留历史任务与流水，不影响下游本地额度。
- 服务为单实例架构，同一数据目录不能同时运行多个进程。进程锁、SQLite 点数/体力预留与内存队列防止透支。

Idempotency-Key 用于防重复提交。同一下游 Key 重复使用已受理编号返回 409，不重复生成、扣点或扣体力。相同 prompt 本身不去重。

## 订阅返回与有效期

普通 Key 的 `/user/subscription` 完全在本地返回：tier=1、NAI5 usage 为零、余额为自己的余额减预留，不需要查询上游。会员也完全在本地返回：tier=3，usage 使用自己的本地体力，与上游状态无关。两种等级的 active/expiresAt 都按下游有效期处理，不使用上游到期时间；永久 Key 不返回 expiresAt。

兼容 [柏宝绘（ST-BaiBai-Image）](https://github.com/baibai-git/ST-BaiBai-Image) 自动添加 `/ai/` 前缀的连接测试：`GET /ai/user/subscription` 与 `GET /user/subscription` 返回相同的下游订阅对象，沿用现有跨域预检、来源限制、`Authorization: Bearer skr_...` 鉴权、密钥有效期和中转暂停检查。柏宝绘接口地址仍填写中转根地址。更新后需重启服务；Docker 部署执行 `docker compose up -d --build`。

兼容 [Langbai NovelAI Studio](https://github.com/2786886095/novelai-image-desktop) 的 `GET /user/data` Token 验证和账号刷新：使用相同的 `Authorization: Bearer skr_...` 鉴权，返回 `{ "subscription": 下游订阅对象 }`。套餐、可用 Anlas 和到期时间与 `/user/subscription` 一致；体力使用本地值，不透传上游的 `usage.timeUntilNextPercent` 连续恢复时间，不返回上游账号资料或密钥。客户端的 Image Endpoint 填写中转根地址，并开启允许向非官方 Endpoint 发送 Token。更新中转后需重启服务；Docker 部署执行 `docker compose up -d --build`。

`relay` 包含等级、到期时间（毫秒）、余额、预留、可用余额、本地体力来源与容量/可用张数/每日恢复量。官方兼容字段 expiresAt 使用秒。后台上游额度查询仍显示真实套餐、到期时间、Anlas 与 NAI5 体力，不使用下游等级。

- 创建 Key 可选永久、从创建起若干天、指定日期时间。
- 编辑可保持到期时间、改为永久、指定时间或续期若干天。
- 续期从“现在与原到期时间的较晚者”起计算。
- 到期返回 HTTP 403 与 `KEY_EXPIRED`，不会自动删除密钥；列表显示已过期，余额、请求记录和流水保留，管理员可以续期。
- 充值不会续期，重新启用不会续期。已受理的请求继续结算。
- 到期判断同时在请求鉴权、排队后和原子预留时执行，不依赖定时任务。

## 控制台与启动

密钥列表的“删除”和密钥详情的“删除密钥”均会先显示确认弹窗。删除后密钥立即失效、从列表与可用余额统计中移除，剩余 Anlas 不再可用，不能重新启用或续期；历史请求、Anlas 流水和用量统计保留。有生成或排队请求的密钥暂不能删除，需等待请求结束。

```powershell
cd D:\code\sakura-nai-relay
npm start
```

也可以双击 `start-local.cmd`。默认监听 `127.0.0.1:3100`，打开 <http://127.0.0.1:3100>。

首次启动读取 `.data/setup-code.txt` 的初始化码，设置至少 12 字符的管理员密码；初始化后该文件删除。管理会话有效 12 小时，使用 HttpOnly Cookie，写操作检查 Origin 与 CSRF。

管理页登录后通过 `GET /admin/api/events` 建立同源 SSE 连接。请求执行与结算、密钥余额和本地体力、Anlas 流水、上游运行状态、兑换码库存和兑换记录变化后自动更新；多个管理页会同步接收。服务端合并 50 毫秒内的变化，连接及重连时发送当前完整快照，每 15 秒发送心跳并核对到期、冷却和每日体力恢复。上游额度在请求结束或修改上游后刷新，并在有管理页连接时每 30 秒统一查询广播。自动推送保留搜索输入和未提交的设置、弹窗表单。退出登录、修改密码或会话到期时关闭对应旧连接，完整 Key 和完整兑换码不进入推送数据。更新后需要重启服务并刷新管理页；反向代理应关闭响应缓冲，参照下方 Caddy/Nginx 配置。

1. 上游设置：添加官方 Persistent API Token，通过启停开关控制是否参与分配。上游名称可留空，自动生成 `上游-Key-1`、`上游-Key-2` 等递增名称；上游和访问密钥分别编号，跳过已占用名称，移除后不复用自动编号，编辑时清空名称也会生成新的编号。保存时仅执行账户查询；账号卡片显示余额和排队请求数。
2. 访问密钥：创建表单默认会员、0 点数、30 天有效期，可自行调整。名称可留空，自动生成 `下游-Key-1`、`下游-Key-2` 等递增名称，跳过已占用名称，删除后不复用自动编号；编辑时清空名称也会生成新的编号。搜索支持名称、完整 Key 或 Key 的任意片段，可定位对应用户。会员体力上限默认 25%，可设置为 0–100%；无需查询或绑定上游即可创建，初始体力直接发满所分配的上限。
3. 在绘图网页填写中转地址和 `skr_` Key。其他域名需在控制台添加允许来源；在“允许的来源”填写 `*` 并保存，即可允许所有来源访问中转接口，仍需有效的 `skr_` Key。指定站点时每行填写一个完整来源，包含协议和端口，不含路径。
4. 通过“编辑 / 续期”调整等级、体力上限和时效，通过“调整点数”增减余额。
5. 在“用量记录 → 请求记录 → 详情”查看请求接口、上游 HTTP 状态和实际转发参数。失败记录同时保存 NovelAI 错误响应原文、SSE 错误事件，或网络中断的底层原因与已收到的最终图片数量。凭据、缓存密钥和图片内容脱敏；图片字段保留字节数与可读取的真实尺寸，便于对照画布参数。超长内容会标明截断。诊断信息单独持久化，仅管理员打开详情时读取，不进入实时列表快照。旧记录未保存的原文无法补回。

完整上下游密钥均 AES-256-GCM 加密保存。下游鉴权使用摘要。完整下游 Key 只在管理员登录、Origin 与 CSRF 校验通过后，通过单独接口查看，不出现在列表或概览中。密钥搜索同样检查管理员会话、Origin 与 CSRF，在服务端匹配并只返回记录 ID，搜索内容通过请求正文发送。备份必须同时保留数据库与 `.data/master.key`。

## 数据库结构

本地体力的一次性迁移已完成，相关脚本已移除。新数据库直接创建包含体力容量、余额、预留和创建时间恢复周期的当前表结构；已完成迁移的数据库直接继续使用，不重新分档、发放初始体力或转换恢复周期。尚未完成本地体力迁移的旧数据库需要先使用保留迁移脚本的旧版本完成升级。

本次更新启动时执行 `src/grant-full-stamina-once.mjs`：将所有未删除会员 Key 的 V5 体力补到各自已分配的上限，包括停用和过期会员。普通 Key 保持零体力，Anlas 点数、有效期和上限不变。先释放服务中断任务的预留，再原子提交补满和 `full_stamina_grant_20261013_v1` 完成标记；执行失败回滚，后续启动可重试，执行成功后重启不再补满。恢复时间仍按原 Key 创建时间每满 24 小时计算，补满时把此前已过周期记为处理完毕，避免消耗后再次追补。

更早、没有 tier 字段的历史数据库仍沿用原来的 archived_keys / archived_jobs / archived_ledger 归档升级流程，那些早期凭据不会重新激活。

原账号权重为零的上游仍迁移为停用，其余保留启停状态。

## Linux / Docker

```bash
cp .env.example .env
# 修改 PUBLIC_ORIGIN=https://relay.example.com
# 并设置 COOKIE_SECURE=true
docker compose up -d --build
docker compose exec relay cat /app/data/setup-code.txt
```

Docker 默认只把端口映射到宿主机回环地址。前面使用 HTTPS 反向代理。宿主机 Caddy 示例：

```caddy
relay.example.com {
    reverse_proxy 127.0.0.1:3100 {
        flush_interval -1
    }
}
```

宿主机 Nginx 可使用下列 `location` 放入已有 HTTPS `server`：

```nginx
location / {
    proxy_pass http://127.0.0.1:3100;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;
    proxy_read_timeout 150s;
    client_max_body_size 32m;
}
```

`PUBLIC_ORIGIN` 必须与浏览器实际打开的协议、域名及端口相同，否则管理写操作会被拒绝。如果控制台通过 IP 访问、而对外中转与兑换页使用域名，可另设 `RELAY_PUBLIC_URL`（兑换结果与控制台显示的中转地址）和 `REDEEM_PUBLIC_URL`（控制台显示的兑换页链接），留空时均回退到 `PUBLIC_ORIGIN`。HTTPS 下使用 Secure Cookie。接口与控制台默认同域。下游请求不设置每分钟限频；同一 Key 和同一上游均串行排队。管理员登录、改密码等管理操作仍保留保护。

配置项见 `.env.example`。`UPSTREAM_ORIGIN` 默认官方图片域名，只能通过服务端环境变量修改，不允许客户端指定目标域名。路由使用白名单，不提供任意 URL 转发。管理页面没有第三方脚本、字体或外部资源。

## 备份与恢复

维护前先停止服务，再备份整个数据目录（Docker 为 `relay-data` 卷），包括 `relay.sqlite`、可能存在的 WAL 文件、`master.key`。**丢失 master.key 无法解密官方 Key**。不要只复制运行中的单个 SQLite 文件。

恢复到另一台机器时，在服务停止状态还原数据目录，删除备份中的 `process.lock`，再启动。未完成请求在启动时自动判为失败并释放预留，不自动重试；已有旧核对任务也自动按失败结算。初始化后普通备份里不再包含有效初始化码。Windows 上应限制数据目录仅当前用户和管理员可读。
